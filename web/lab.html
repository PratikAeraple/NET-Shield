LAB NOTES / 01

Isolated failures.
Observable recovery.

The repeatable lab creates only named containers on Docker internal networks. The disposable fixture has no published ports and no production route.

Scenarios executed

  • DNS failure — an unknown service name returns a resolver failure; the same-network service resolves normally.
  • Segmentation — a service attached only to a separate internal network cannot be resolved or reached from the probe network.
  • Incorrect port — TCP/8081 on the fixture is closed while TCP/8080 serves the expected identity.
  • Application timeout — a delayed handler exceeds the 100 ms client deadline and is reported as a timeout.
  • TLS hostname — a generated, trusted test certificate with a deliberately wrong SAN is rejected by standard hostname verification.
  • Service unavailable/recovery — stop only the lab web container, observe the failed connection, start it again and verify its identity response.

Evidence status: LAB VALIDATED by `lab/run.sh`; no OPNsense ACL, physical VLAN, DHCP service, VPN or production incident is implied.

Run it safely

./lab/run.sh

The script refuses to replace an existing runtime directory. It generates a one-day test certificate in an ignored directory, runs the short-lived tests, then removes only the named Compose project, its networks and its temporary certificate. It does not run prune commands or remove volumes.

What this lab cannot prove

Docker network isolation is not equivalent to physical VLAN enforcement or a routed firewall ACL. OPNsense deployment remains PLANNED / REQUIRES VIRTUALIZATION. No arbitrary Internet Nmap scan is performed.
