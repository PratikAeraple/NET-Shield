A proposed segmentation model with named source roles, explicit inter-zone services and a default-deny close.

Five segments

VLAN 10 ADMIN (`192.0.2.0/26`); VLAN 20 SERVER (`198.51.100.0/26`); VLAN 30 APPLICATION (`203.0.113.0/26`); VLAN 40 TESTING (`192.0.2.64/26`); VLAN 50 MONITORING (`198.51.100.64/26`). These RFC 5737 TEST-NET examples are documentation-only and are not deployed BruteHost ranges.

Testing receives no route to production. Monitoring gets read-only access to explicit health endpoints. Administration uses named devices or a controlled bastion and does not become a general application client network.

Core service design

  • DNS: approved resolver pair, explicit forwarding and separate transport/DNSSEC checks.
  • DHCP: non-overlapping per-VLAN scopes, infrastructure reservations, short testing leases and relay only on routed client interfaces.
  • Routing: stateful inter-zone routing at the firewall; no dual-homed bypass; TESTING cannot route to production.
  • VPN: future named users, MFA, narrow address pool, no shared keys, no WAN management UI.
  • Management: separate admin identity and path, auditable changes, console recovery and prepared rollback.

Deployment boundary

OPNsense deployment is PLANNED / REQUIRES VIRTUALIZATION. No firewall VM, switch VLAN, DHCP server, VPN account, physical packet capture or live ACL is claimed. The Docker lab validates only internal Docker name/service separation and selected failure cases.
